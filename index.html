下一句预测接口手册

用户看完一轮回答后，输入框里先显示一句灰色的「下一句」，即用户最可能接着说的话；按 Tab 填进输入框，回车发送。后端用模型配置里的结果模型，读本会话最近几轮问答和本轮「猜你想问」生成这句话。

接口 POST /suggest/next 调用时机 收到 end 帧后 返回 同步 JSON，约 1–2 秒 更新 2026-10-14
●后端状态：接口已上预发，与智能问数 /ask/stream 同一服务地址，可以联调。

对接步骤

回答结束（end 帧）→调 /suggest/next→输入框显示灰字→Tab 填入→回车发送
  1. 问数流式接口（/ask/stream、/ask/stream/cc、/ask/stream/react、/ask/stream/codex）收到 end 帧后，立即调 POST /suggest/next，带这次问数用的 session_id、项目和 user_id。把 end 帧里的 session_turn_id 记下来，用于第 2 步核对。
  2. 返回的 text 不为空，且 turn_id 等于刚记下的 session_turn_id：输入框为空时，把 text 显示成灰字（占位符的位置），旁边提示「Tab 采用」。
  3. 用户按 Tab（或光标在末尾时按 →）：把 text 填进输入框，不自动发送。用户可以先改再回车，发送走正常问数。

交互原型

可以直接操作：点一张推荐卡片提问，回答结束后输入框出现灰字，按 Tab 填入；打一两个字看灰字怎么跟随。右侧「开发视图」可以切换本轮怎么结束、接口返回什么，时间线逐帧显示什么时候调接口。界面按智能问数页面画，回答正文用占位条代替，耗时压缩到两三秒。

在新窗口全屏打开（带平台导航栏和左侧菜单）

什么时候调

场景调不调说明
流式回答收到 end 帧调主要时机。服务端在发 end 之前已经写好本轮记录，这时调一定读得到
打开历史会话（已有问答）调一次对最后一轮预测。该轮生成过的话直接返回已有结果
新会话、首页（还没有问答）不调调了也只返回空 text
收到 cancelled（用户停止）或 error不调本轮没有完整回答，不出灰字
同一轮已经拿到过结果不再调用户把输入删空时，直接复用已拿到的 text。重复调用不会多花钱（走缓存），但没必要

通用约定

项说明
身份user_id 必填，与调问数接口时传的是同一个值。只能预测自己发起的会话。
项目project（项目名）或 project_id，传法与问数接口相同，数字或字符串都行。只看该项目下的轮次。
依据本会话最近 3 轮的提问与回答（含取数结果），以及最后一轮回答下方展示的「猜你想问」。
模型模型配置页「结果与分析模型」的主模型，失败自动转兜底模型。
数据只读会话记录，不查数仓，不需要查数凭据。
复用同一轮只生成一次，结果随该轮保存，再调直接返回（cached 为 true）；用户问了新一轮自然换新结果。
鉴权与问数接口相同：服务端开启口令时带请求头 X-Api-Token。
耗时首次通常 1–2 秒，已生成过的几乎即时。主模型 10 秒左右不出字会转兜底模型，这时总共约 15 秒。前端建议 20 秒超时，超时直接放弃、不出灰字；结果回来时输入框已经有内容，就不再显示。

预测下一句

POST/suggest/next

对会话最新一轮预测用户下一句。请求体与会话订阅接口相同。

请求
{
  "session_id": "1001",
  "project_id": 31,
  "user_id": "<user_id>"
}
字段必填说明
session_id是问数时用的会话号，字符串或数字，最长 128 字符
user_id是会话发起人
project / project_id二选一同问数接口
响应
{
  "session_id": "1001",
  "project": "猎鱼达人3D",
  "turn_id": "9f2c4e1a-7b3d-4c8e-a1f0-2d6b8e3c5a71",
  "text": "近 7 天次日留存为什么比上周低？",
  "cached": false,
  "elapsed_ms": 1236
}
字段说明
turn_id预测依据的轮次，即会话最新一轮，与该轮 end 帧里的 session_turn_id 相同。会话还没有问答时为空串
text灰字内容，单行。空串表示这一轮不出灰字（会话为空、模型没把握或输出不可用），保持默认占位即可
cached是否直接返回了该轮已生成的结果，仅供排查
elapsed_ms本次耗时（毫秒），仅供排查
session_id / project回显，project 是解析后的项目名

灰字交互

情况前端怎么做
输入框为空显示灰字，位置同占位符，颜色比正文浅；此时隐藏默认占位「请输入你的问题…」。旁边放一个小的「Tab 采用」提示，否则用户不知道能按 Tab
用户输入的是灰字开头（逐字一致）继续显示灰字剩下的部分，接在用户输入后面
用户输入了别的隐藏灰字；用户删空后重新显示，不用再调接口
按 Tab灰字可见时拦截（preventDefault），把整句填进输入框；灰字不可见时不拦截，保持正常的焦点切换
按 →灰字可见且光标在输入末尾时，同 Tab
中文输入法正在组字不拦截 Tab 和回车（compositionstart 到 compositionend 之间，或 keyCode === 229）
采用之后只填入，不自动发送；用户回车或点发送才问
用户发送新问题、切换会话、新建会话清掉灰字；还在路上的请求，回来后按 turn_id 核对，不是最新一轮就丢弃
请求还没返回保持默认占位，不需要加载状态
读屏灰字是视觉提示，同时用 aria-describedby 或 aria-live="polite" 读出「建议输入：…，按 Tab 采用」

text 从哪来

前端不需要按来源分支处理，也不要因为和某个按钮文字相同就去标记那个按钮：灰字不一定来自「猜你想问」。这里只说明为什么有时和按钮一样、有时不一样。

情况text
用户最可能的下一步正好是某条「猜你想问」那个按钮的原文，逐字相同
用户更可能确认、改口或提要求（按钮里没有）模型用用户口吻写的一句，一般不超过 30 字，如「可以，以后每天按这个口径发我」
模型看不出下一步、输出过长，或和用户本会话说过的话重复空串

模型被要求只引用回答里出现过的对象和数字，不编回答里没有的指标、维度或数字；它是建议，用户采用后仍可修改。

错误

错误走 HTTP 状态码，响应体 {"detail": "…"}（422 时 detail 是校验明细数组）。灰字是锦上添花，任何错误都静默处理：不出灰字，也不提示用户。

状态码含义
401口令错误
403没带 user_id，或会话不属于该用户
422请求体不合法（如缺 session_id、为空或超长）
502结果模型调用失败（主模型和兜底都没成）

会话还没有问答不算错误：返回 200，turn_id 和 text 都是空串。
